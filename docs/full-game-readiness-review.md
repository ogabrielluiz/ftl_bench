# Full-game readiness review

Reviewed 2026-10-10 against the frozen visual clock 2 sources. This is a read-only code assessment; no game or model was launched. The runner can attempt a full game, but current challenge acceptance does not establish an uninterrupted game ending in native victory or defeat.

The full-game path has no implicit sector cutoff. `--stop-after-sector` defaults to absent; only that option installs the sector stopping predicate and marks the trial `sector_progress` ([run_visual.py:304,327–343,373–376](../adapter/run_visual.py)). Native terminal state takes priority over both goal predicates and budgets, including the final allowed decision ([run_visual.py:188–200,254–260](../adapter/run_visual.py)); the final-decision and idle-boundary tests cover this with synthetic observations ([test_visual_runner.py:285–292,340–346](../harness/tests/test_visual_runner.py)). No terminal-precedence correction is indicated by this review.

## Material gaps and limits

1. **Real terminal capture remains an acceptance gap.** Defeat comes from `gui.gameover`; victory comes first from the native helper, whose predicate is `alreadyWon || (gameover && gameOverScreen.bVictory)` and returns false when `world.bStartedGame` is false ([ftl_bench_dev.lua:2020–2023,2059–2066](../mod/ftl_bench_bridge/dev/ftl_bench_dev.lua), [native patch:143–148](../native/patches/0003-visual-io.patch)). The native blocker stops positive advancement on terminal flags, while the capture writer requires a paused render ([Benchmark_VisualEngine.inc:251,347–356](../native/include/Benchmark_VisualEngine.inc)). A live terminal transition must demonstrate that these conditions still publish a synchronized final PNG and the correct boolean before the runner stops. Mock terminal tests cannot establish this. The reviewed older full-game attempts ended at infrastructure failure or human interruption, rather than a native terminal result ([0420 report](../harness/runs/validation/visual-v1/sol-fullgame-20261009T0420/visual-report.json), [0429 report](../harness/runs/validation/visual-v1/sol-fullgame-20261009T0429/visual-report.json)).

2. **Declared budgets can end a healthy game early.** Defaults are 300 decisions, 14,400 wall seconds and eight consecutive empty zero-frame decisions ([run_visual.py:306–309](../adapter/run_visual.py)). With at most 600 fixed frames per decision, 300 decisions permit at most 3,000 nominal simulated seconds; UI-only decisions reduce that total ([visual_session.py:188–195](../harness/src/ftl_bench/visual_session.py)). Whether this permits completion is unmeasured. Budget exhaustion is an incomplete game, even though its lifecycle status is `completed`. Preserve the existing limits for the declared cohort; a larger budget requires a newly declared protocol, as already specified in [visual-experiment-protocol.md:121–128](visual-experiment-protocol.md).

3. **The wall budget is a between-decision limit.** The loop checks elapsed time before inference, then dispatches the returned action without another deadline check ([run_visual.py:198–221](../adapter/run_visual.py)). A model request has its own default 300-second timeout; a 600-frame acknowledgement may wait 30 seconds ([visual_agent.py:348,408–413](../adapter/visual_agent.py), [visual_session.py:248–250](../harness/src/ftl_bench/visual_session.py)). A call begun just before the wall limit can therefore produce a step after it expires. Record this as the existing budget semantics; a strict deadline would need remaining-time propagation and a pre-dispatch check in a later protocol.

4. **Technical interruption ends the trial.** Provider timeout, invalid response, capture failure and outside input are classified and propagated; the runner does not resume the same game ([visual_agent.py:408–413](../adapter/visual_agent.py), [run_visual.py:213–218,263–271](../adapter/run_visual.py)). Protected cleanup stops the owned game before restoring saves; restoration refuses a remaining or unowned process ([protected_game.py:97–117,177–187](../harness/src/ftl_bench/protected_game.py)). This supports honest exclusions, but uninterrupted full-game readiness still needs a completed long run and a separate live interruption test. Cleanup exceptions remain visible in the manifest even when an earlier native terminal record exists ([test_visual_runner.py:505–514,539–550](../harness/tests/test_visual_runner.py)).

5. **Later-game coverage remains open.** The current matrix runs combat, fire recovery and repair/escape fixtures; its frozen scope explicitly excludes full-game scores ([run_visual_experiment.py:24,118](../scripts/run_visual_experiment.py)). The fuel-wait fixture proves waiting completes and an event boundary appears, rather than accepting the recovery offer and departing ([validate_visual_sector.py:178–183](../scripts/validate_visual_sector.py)). Actual recovery-choice continuation and the final-sector/flagship path remain relevant obstacles to prove through ordinary visual inputs. The seed identity checked at startup does not itself prove a reproducible full native RNG stream; keep that separate from terminal completion.

## Proposed acceptance checklist

- Run the first-sector trial with the explicit sector target; accept only observed transition or native loss, and retain any cutoff as incomplete.
- Run full-game conditions with `--stop-after-sector` absent, the normal victory objective, and the already declared model, mode, seed and budgets. Make no mid-trial fixture edits or manual gameplay corrections.
- Continue through ordinary recovery choices and any late-game screens encountered. Archive each exact input, native acknowledgement, fixed-step count and resulting screenshot.
- Require an uninterrupted attempt ending `native_victory` or `native_game_over`; retain budget, provider, transport and operator stops as their actual categories. A defeat establishes a completed game, not victory-path acceptance.
- For each observed terminal type, inspect the final PNG alongside native `game_over`/`victory`, final score, trajectory end, report and manifest. Exercise terminal-on-last-decision behavior with the installed build; accept partial frame budgets only when their native count and blocking state agree.
- Verify no owned FTL process remains, every original save hash is restored, the production bridge is restored, and the immutable run audit passes. A cleanup failure prevents acceptance even after native victory.
- In a separate disposable trial, interrupt during model waiting and during positive advancement; verify honest interruption classification, no further inputs, retained evidence and completed cleanup. Preserve recoverable backups if cleanup fails.
- Report full-game repeatability and matched-comparison readiness only from those full-game artifacts. The clock/challenge matrix alone supplies neither claim.
